\section{Material Evolution Knowledge Hypergraphs}
\label{sec:mekh}

A \emph{Material Evolution Knowledge Hypergraph} (MEKH) is a directed labeled multi-hypergraph $\Hcal(M,E)$~\cite{ouvrardHypergraphsIntroductionReview2020}. Each vertex $m\in M$ is a material identified by a six-digit Harmonized System code~\cite{hscode}; HS-6 is the finest level at which codes are internationally comparable and at which UN Comtrade reports trade, so a MEKH can be joined directly to trade flows (Section~\ref{sec:application}). Each hyperedge $e=(e_s,e_t)\in E$ is an industrial or chemical process $\mathbf{P}_e$ transforming an input set $e_s\subset M$ into an output set $e_t\subset M$; $\ell(e)=\mathbf{P}_e$ labels it, and several processes with the same $(e_s,e_t)$ are distinct parallel hyperedges. A hyperedge carries a narrative description, an LLM-estimated operating-scale score in $[0,1]$, and a list of references, each with a source-quality score, a content-relevance score, and the URL from which an analyst can audit it.

Because vertices are HS-6 codes, purification steps whose input and output share a code (e.g., crude and electronic-grade germanium metal, both HS~811292) appear as self-loops; we keep them, as they are real chokepoints, but they are invisible to code-set analyses.

Algorithm~\ref{alg:tdn-pipeline} gives the outer loop. Starting from seed materials, each iteration calls \textsc{ProcessGeneration}, which queries auxiliary resources $A$ (HS-code search, web search, encyclopedic sources, and the reference cache) for processes that produce or consume known materials, admits those passing the gates of Section~\ref{sec:gates}, and adds their inputs and outputs as new vertices.

\begin{algorithm}[h]
\caption{Bottom-Up \toolname (System Process Overview)}
\label{alg:tdn-pipeline}
\begin{algorithmic}[1]
\REQUIRE number of iterations $n$, seed vertex set (seed materials) $s$, auxiliary hypergraph data $A$, universe of allowable vertices (materials) $\mathcal{V}$
\STATE $\text{Hyperedges (Processes)} \gets \emptyset$
\STATE $\text{Vertices (Materials)} \gets s$

\FOR{$i = 1, \ldots, n$}
    \STATE Update Hyperedges from $\text{ProcessGeneration}(\text{Vertices}, V)$
    \STATE Each hyperedge has input and output sets $e_{s}, e_{t} \subset \mathcal{V}$
    \STATE Update Vertices with $e_{s} \cup e_{t}$ for each new process
\ENDFOR
\RETURN $\Hcal = (\text{Vertices}, \text{Hyperedges})$

\end{algorithmic}
\end{algorithm}

\subsection{Admission gates}
\label{sec:gates}
A candidate process becomes a hyperedge only if: (G1) every precursor and product resolves to a valid HS-6 code; (G2) it cites at least $k_{\min}=2$ references from at least $d_{\min}=2$ distinct web domains; (G3) its process score is defined and $\ge\tau$; and (G4) its operating-scale score is at least $0.4$. Processes failing G2--G4 after the maximum number of review rounds are removed by the \emph{purge} task, the only task with no LLM. Gates are the reason the pipeline's errors are auditable: an analyst who doubts a hyperedge can open its references and see why it was admitted.

\subsection{Iteration and modes}
Process discovery runs in \emph{create} mode for materials with no processes and in \emph{edit} mode otherwise; in edit mode the agent sees the existing processes and their reference scores and may add references, revise inputs/outputs, or remove a process it now judges unsupported. Upstream/downstream expansion sends every unresolved precursor or product to the material finder, and the next iteration discovers processes for the new materials. Iteration stops after $n$ rounds or when no new materials are found.

\subsection{Run configuration}
\label{sec:runconfig}
All MEKHs in this paper were generated with \GenModel{} (temperature: \GenTemp{}), $n=5$ iterations, $k_{\min}=d_{\min}=2$, and $\tau=\GenTau{}$. Prompts, schemas, and the configuration file are in the supplementary material.
