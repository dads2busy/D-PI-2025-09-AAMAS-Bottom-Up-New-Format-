\section{Material Evolution Knowledge Hypergraphs}
\label{sec:mekh}

A \emph{Material Evolution Knowledge Hypergraph} (MEKH) is a directed labeled multi-hypergraph $\Hcal(M,E)$~\cite{ouvrardHypergraphsIntroductionReview2020}. Each vertex $m\in M$ is a material identified by a six-digit Harmonized System code~\cite{hscode}; HS-6 is the finest level at which codes are internationally comparable and at which UN Comtrade reports trade, so a MEKH can be joined directly to trade flows (Section~\ref{sec:application}). Each hyperedge $e=(e_s,e_t)\in E$ is an industrial or chemical process $\mathbf{P}_e$ transforming an input set $e_s\subset M$ into an output set $e_t\subset M$; $\ell(e)=\mathbf{P}_e$ labels it, and several processes with the same $(e_s,e_t)$ are distinct parallel hyperedges. A precursor or product that the generating agent cannot assign a clear HS-6 code (e.g., a minor reagent or a discarded waste stream) is recorded on the hyperedge as a plain name rather than a typed vertex; such untyped materials are excluded from $M$ and from code-set analyses, and Section~\ref{sec:experiments} reports how many hyperedges carry them. A hyperedge carries a narrative description, an LLM-estimated operating-scale score in $[0,1]$, and a list of references, each with a source-quality score, a content-relevance score, and the URL from which an analyst can audit it.

Because vertices are HS-6 codes, purification steps whose input and output share a code (e.g., crude and electronic-grade germanium metal, both HS~811292) appear as self-loops; we keep them, as they are real chokepoints, but they are invisible to code-set analyses.

Algorithm~\ref{alg:tdn-pipeline} gives the outer loop. Starting from seed materials, each iteration calls \textsc{ProcessGeneration}, which queries auxiliary resources $A$ (HS-code search, web search, encyclopedic sources, and the reference cache) for processes that produce or consume known materials, admits those passing the gates of Section~\ref{sec:gates}, and adds their typed inputs and outputs as new vertices.

\begin{algorithm}[h]
\caption{Bottom-Up \toolname (System Process Overview)}
\label{alg:tdn-pipeline}
\begin{algorithmic}[1]
\REQUIRE number of iterations $n$, seed vertex set (seed materials) $s$, auxiliary hypergraph data $A$, universe of allowable vertices (materials) $\mathcal{V}$
\STATE $\text{Hyperedges (Processes)} \gets \emptyset$
\STATE $\text{Vertices (Materials)} \gets s$

\FOR{$i = 1, \ldots, n$}
    \STATE Update Hyperedges from $\text{ProcessGeneration}(\text{Vertices}, A)$
    \STATE Each hyperedge has input and output sets $e_{s}, e_{t} \subset \mathcal{V}$
    \STATE Update Vertices with the HS-coded members of $e_{s} \cup e_{t}$ for each new process
\ENDFOR
\RETURN $\Hcal = (\text{Vertices}, \text{Hyperedges})$

\end{algorithmic}
\end{algorithm}

\subsection{Admission gates}
\label{sec:gates}
Materials are typed with HS-6 codes assigned by the classification, finder, and manufacturing agents using an HS-code search tool (Table~\ref{tab:agents}); these codes are not independently verified against the official nomenclature, and a precursor or product none of them can code is recorded as a plain string rather than resolved to a vertex in $M$ (Section~\ref{sec:mekh}). Deterministic, LLM-free checks recur at several points rather than in one gate: after every process-generation pass, processes with a scale score below $0.4$ are purged; after every reference-review pass, individual references with a content-relevance score below $0.3$ are dropped from their process; and the dedicated \emph{purge} task removes a process whose evidence score is defined and below $\tau$, whose evidence score is still undefined once \emph{every} reference on it has been reviewed (including a process with no references at all), or whose scale score is below $0.4$. The evidence score, $\frac{1}{|R^\star|}\sum_{r\in R^\star} q_c(r)\min(2q_s(r),1)$ over the top references $R^\star$, is defined only once every reference on the process has been reviewed \emph{and} at least $k_{\min}=2$ of them, spanning at least $d_{\min}=2$ distinct domains, qualify as top references; a process with references still unreviewed after the maximum number of review rounds fails this ``all reviewed'' condition and is retained unscored rather than purged, and Section~\ref{sec:experiments} reports how often this happens. An analyst who doubts a hyperedge can still open its references and see why it survived these checks.

\subsection{Iteration and modes}
Process discovery runs in \emph{create} mode for materials with no processes and in \emph{edit} mode otherwise; in edit mode the agent sees the existing processes and their reference scores and may add references, revise inputs/outputs, or remove a process it now judges unsupported. Expansion routes every coded but unresolved (\emph{suggested}) precursor to the material finder; plain-string precursors and all products are not routed. The next iteration discovers processes for the newly typed materials. Iteration stops after $n$ rounds.

\subsection{Run configuration}
\label{sec:runconfig}
All MEKHs in this paper were generated with \GenModel{} (temperature: \GenTemp{}), $n=5$ iterations, $k_{\min}=d_{\min}=2$, and $\tau=\GenTau{}$. Prompts, schemas, and the configuration file are in the supplementary material.
